# 换成自己的互动游戏

[English](../en/REPLACE-EXAMPLE.md)

如果已经试过示例，想把它改成守塔、竞速等玩法，这一页说明从哪里改。先保留测试弹幕、观众身份和广播画面，把游戏规则逐步换掉。

这一步需要修改代码，可以配合 [AI 编程助手](WORKFLOW.md)完成。目前还没有通过一个配置文件切换任意游戏的插件接口。

| 层 | 沿用的思路 | 要改的内容 |
| --- | --- | --- |
| 平台 | 授权、稳定 ID、去重、收据 | 平台字段、权限、礼物与价值解释 |
| 互动与模型 | 冷却、排队、有限动作、记忆、语音调度 | 指令、角色设定、动作枚举与触发条件 |
| 游戏 | 权威状态、只读画面、归属和高光 | 规则、胜负、道具、美术与镜头 |

以合作守塔为例：

1. 定义免费输入：发“修补”修复城墙，并显示冷却。
2. 在 `examples/` 新建自己的游戏，先用合成事件完成修补与反馈，不接支付。
3. 定义修补、部署、升级等允许动作。游戏规则结算资源，聊天不能直接变成函数名执行。
4. 借鉴现有去重、收据、头像、回复队列；移除人族/魔族、军团和代次假设。`LiveGame` 与 `PixelWorld` 相互依赖，只改标题不能换游戏。
5. 如需 AI，一起修改提示、JSON Schema、验证器和执行端；只接受定义好的动作，失败由本地规则继续。
6. 建独立画面网址与管理动作，让 OBS 只加载画面。
7. 用自己的平台当前目录绑定礼物，先验证重复事件只生效一次，再进行真实授权联调。

改完后，用同一个测试身份连续发命令，再切到另一个身份，确认操作只影响各自的角色。断开 AI 后基础玩法应继续；重放同一礼物事件应只奖励一次。最后按[运行检查](VALIDATION.md)确认启动与广播画面。

采用流程不要求复制示例的角色故事。复用美术与音频时则必须同时保留各自许可。
