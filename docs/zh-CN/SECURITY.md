# 安全配置与数据管理

[English](../en/SECURITY.md)

连接直播平台和模型服务时，请在本机配置凭证，并使用独立的游戏画面源。以下说明帮助你管理自己的配置、观众数据和运行权限。

## 本地存储

| 路径 | 用途 |
| --- | --- |
| `.local/game.sqlite` | 战局、部队归属、事件收据和互动历史 |
| `.local/connections.sqlite` | 平台连接设置和待处理事件，可能包含已填写的凭证 |
| `.env` | 可选模型服务配置 |

启动器限制目录和文件权限；数据库未单独加密，同一操作系统账户下的程序仍可能读取。停止程序后可删除 `.local/` 和 `.env` 来清除本地存档与配置；备份和供应商侧记录需另行管理。

## 模型权限

模型接收有限战况和选中的观众消息，返回结构化台词与策略。服务器验证动作、角色身份和消息有效期后执行。保持这一边界：不向角色开放 shell、任意文件读写或电脑控制工具。

昵称、消息和历史对话都是外部输入。不要把这些文本拼接进命令、SQL 或源码。对话内容过滤需要按你的受众配置和演练。

## 服务与直播输出

管理端口默认只监听本机，不应直接暴露到公网。来源校验和随机令牌用于本地管理；改为公网服务时需要另行设计身份验证与访问控制。

Node 进程拥有运行它的用户权限。需要更强隔离时，使用低权限账户、容器或虚拟机，限制挂载和网络范围。OBS 使用专门的画面网址，并通过录制文件检查音频和画面，具体步骤见 [B站与 OBS](BILIBILI-AND-OBS.md)。

## 观众数据

跨天记忆会保存互动记录，即使关闭 AI，弹幕仍可能被记录。当前版本没有自动保留期限或逐个观众彻底删除的工具；撤回会清理展示和对话状态，但事件收据仍可能保留原文。因此不要把撤回按钮当成完整的数据删除。

需要清除全部本地记录时，先停止服务，再按上文移走或删除 `.local/`；这也会清除游戏存档及平台连接配置。若要面向真实观众长期运行，先补齐保留期限和逐人删除机制，并说明数据用途。调试和提交 Issue 时使用模拟身份与消息。

## 发布自己的版本

运行 `npm run privacy:check`，核对 `release-files.json` 后再打包。`.env`、运行数据库、日志和浏览器资料不要加入清单。扫描器只检查常见路径与凭证模式；图片、视频和新增文件仍需人工检查。保留第三方素材的作者、来源和许可证。

报告安全问题时，提供受影响版本、最小复现和预期结果。不要把真实凭证或观众记录贴到公开 Issue。
